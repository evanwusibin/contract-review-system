## 2. 冲突解决规则

1. 产品范围冲突时以 A1、A2 为准。
2. 数据模型或状态机冲突时以 A4 为准；代码实现只能映射它，不能另建平行模型。
3. 模块边界和接口契约冲突时以 A3 为准。
4. 切片交付顺序和验收标准冲突时以 A5 为准。
5. 当前交付状态冲突时以 `00_可执行交付基线.md` 为准。
6. 代码和测试结果仅能证明 `implemented` 或 `verified`；不得反向改变未批准的产品规则。

## 3. 跨文档不变量

```
导入 → 质量诊断 → 解析 → 规则审查 → 审批建议 → 人工确认 → 版本保存
```

- 原始附件、解析结果、规则命中、人工结论和审计日志分开保存。
- 任务状态与审批建议状态分离。
- `insufficient_evidence` 不得生成 `confirmed` 建议。
- `SIMULATED_ONLY` 操作必须明确标注。
- HP-001 在来源确认前只能是候选规则。

## 4. 状态口径

| 状态 | 含义 |
|---|---|
| `draft` | 内容存在，尚未完成核验 |
| `review` | 准出材料完整，等待评审 |
| `approved` | 允许按指定契约实施 |
| `implemented` | 已有实现，未必已验证 |
| `accepted` | 已记录可复现的验收证据 |
| `blocked` | 受依赖阻塞 |
