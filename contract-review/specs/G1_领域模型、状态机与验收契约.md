# G1 领域模型、状态机与验收契约

> **状态**：draft。本文定义合同评审系统的领域对象、状态转换不变量和验收契约。

## 1. 核心领域对象

### 1.1 `ApprovalTask`
```
id: UUID
external_task_key: str (UNIQUE)
title: str
contract_type: "after_sales" | "sales"
status: TaskStatus
recommendation_status: RecStatus
current_version_id: UUID | None
blocked_reason: str | None
```

### 1.2 `ApprovalAttachment`
```
id: UUID
task_id: UUID (FK)
version_no: int (>= 0, UNIQUE per task)
file_sha256: str (64 chars, UNIQUE per task)
storage_key: str
quality_status: "unknown" | "usable" | "low_quality" | "unreadable"
is_current: bool
```

### 1.3 `ContractParse`
```
id: UUID
attachment_id: UUID (FK, UNIQUE)
status: "queued" | "running" | "succeeded" | "failed"
extracted_payload: JSON
quality_score: float | None
```

### 1.4 `RuleHit`
```
id: UUID
parse_id: UUID (FK)
rule_code: str
result: "hit" | "not_hit" | "insufficient_evidence"
severity: "low" | "medium" | "high"
evidence: JSON (page, snippet, confidence)
```

### 1.5 `ReviewResult`
```
id: UUID
task_id: UUID (FK)
recommendation: "pass" | "reject" | "manual_review"
status: "draft" | "pending_confirmation" | "confirmed" | "rejected" | "returned"
required_roles: list[str]
confirmed_roles: list[str]
is_simulated: bool
```

## 2. 任务状态机

```
[*] --> imported --> parsing --> reviewing --> awaiting_confirmation --> confirming --> confirmed --> [*]
                |            |
                v            v
             blocked    rejected_recommendation
                |
                +--(重新上传)--> parsing
                +--(人工补录)--> reviewing

confirming --(驳回/补证)--> reviewing
```

### 状态转换规则

| 当前状态 | 目标状态 | 前置条件 |
|---------|---------|---------|
| `imported` | `parsing` | 附件存在且类型支持 |
| `parsing` | `reviewing` | 解析成功且关键字段可用 |
| `parsing` | `blocked` | 文件损坏/OCR不可用 |
| `reviewing` | `awaiting_confirmation` | 规则执行完成 |
| `reviewing` | `rejected_recommendation` | 关键字段缺失 |
| `awaiting_confirmation` | `confirming` | 建议生成完成 |
| `confirming` | `confirmed` | 所有 required_roles 已确认 |
| `confirming` | `reviewing` | 驳回或要求补证 |
| `blocked` | `parsing` | 重新上传成功 |
| `blocked` | `reviewing` | 人工补录完成 |

非法转换返回 `INVALID_STATE_TRANSITION` 并写入审计日志。

## 3. 审批建议状态机

```
draft → pending_confirmation → confirmed | rejected | returned
```

- `confirmed` 表示责任人确认建议，不表示系统自动审批。
- `returned` 表示退回重新审查。

## 4. 不变量

1. 一个 `approval_task` 可关联多个附件；同一合同版本对应一个 `contract_parse`。
2. 同一 `(task_id, version_no)` 唯一；同一 `(task_id, file_sha256)` 唯一。
3. `RuleHit.result = "insufficient_evidence"` 时，对应 `ReviewResult` 不得进入 `confirmed`。
4. `ReviewResult.is_simulated = true` 时，前端必须显示 `SIMULATED_ONLY` 标记。
5. `required_roles` 中的每个角色都必须存在于 `confirmed_roles` 才能进入 `confirmed`。
6. 删除采用逻辑删除（`deleted_at`），历史记录不可物理删除。

## 5. 验收契约

| Case | 场景 | 预期结果 |
|---|---|---|
| GD-001 | 清晰售后合同 | `reviewing`；无高风险；字段证据可定位 |
| GD-002 | 缺失乙方 | 命中 `RULE-PARTY-001` 高风险；建议驳回 |
| GD-003 | 低清扫描件 | `blocked` 或 `manual_review`；显示补录入口 |
| GD-004 | 质保缺失 | 命中 `RULE-WARRANTY-001` |
| GD-005 | HP-001 未确认 | 仅人工复核；不得自动驳回 |
| GD-006 | 版本修订 | 两个版本可独立查看 |
| GD-007 | 多角色会签 | 缺任一角色时不能确认 |
| GD-008 | 幂等重试 | 不重复创建任务或版本 |
